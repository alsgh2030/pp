# HGSS 전투 메커니즘 분석 및 Python 구현 범위

기준은 `ctrl-cheeb-del/pokeheartgold` 커밋 `01eeeb4b96087cb94c84de3045e9f2d4ef00061b`입니다. 최신 세대 규칙을 섞지 않고, 해당 소스에서 읽은 4세대 계산 순서를 사용합니다. 저장소의 원본 일치 빌드 주장은 이번 Python 구현의 정확도 인증이 아닙니다. 실제 NDS 실행과 대조한 것은 아니며 지원 범위의 정수 계산과 상태 전이를 단위 테스트했습니다.

## 1. 프로젝트의 세 층

| 구성 | 내용 | 원작 재현 수준 |
|---|---|---|
| 원본 연구 자료 | AI C 코드, AI 바이트코드, 전투 계산 코드, 출처 해시 | 지정 커밋에서 그대로 추출 |
| 계산기 | 실능력치, 스피드, 우선도, 대미지, 명중·급소 확률 | 아래 지원 조건에 한해 소스 기반 구현; 전체 엔진 동일성 미검증 |
| 실험 AI·배틀 | 기술 점수와 설명, 교체·회복 선택, 싱글 턴제 진행 | 새로 작성한 교육용 정책/간소화 시뮬레이터 |

**Python AI는 원작의 109개 명령을 실행하는 완전한 스크립트 인터프리터가 아닙니다.** 원작 알고리즘의 초기 점수/가감점/동점 무작위라는 구조를 사용하며 구체적인 배점은 수정하기 쉽게 새로 설계했습니다. 원작 소스 추출은 완전한 연구 자료 보존이고, 실행 가능한 Python 이식은 명시된 범위입니다.

## 2. 실능력치: IV·EV·레벨·성격

`make_pokemon()`은 원본 `personal.json`의 종족값을 읽습니다.

- HP: `floor((2×종족값 + IV + floor(EV/4)) × 레벨/100) + 레벨 + 10`
- 나머지 능력치: 위 계산에서 `+레벨+10` 대신 `+5`, 이후 성격 보정 1.1/0.9배를 적용하고 버립니다.
- 껍질몬 HP는 1입니다.
- IV 0~31, EV 각 0~255 및 합계 510 이하, 레벨 1~100을 검사합니다.
- 성격은 25종을 지원합니다. 예: `TIMID`는 스피드 증가·공격 감소.
- 기본값은 레벨 50, IV 31, EV 0, 무보정 성격입니다.

특성·도구는 기본적으로 `NONE`입니다. 실제 종의 특성을 자동으로 적용하지 않으므로 비교 실험 시 `ability`를 명시하세요. 종별 원래 특성 목록은 데이터에 보존했습니다. 실제 게임에서 가능한 기술 습득 조합이나 특성 조합까지 검증하는 팀 빌더는 아닙니다.

## 3. 스피드와 행동 순서

원본 `src/battle/battle_util.c`의 약 970~1240행을 검토했습니다. 각 곱셈·나눗셈 뒤 정수 결과를 사용합니다.

1. 기본 스피드에 능력치 랭크를 적용합니다. +2랭크는 2배, -2랭크는 1/2배입니다.
2. 단순(Simple)은 랭크 변화를 두 배로 하되 -6~+6에 제한합니다.
3. 쓱쓱·엽록소는 해당 날씨에 2배입니다. 에어록·날씨부정이 활성화되면 날씨 효과를 억제합니다.
4. 검은철구·교정깁스는 1/2배, 구애스카프는 1.5배입니다. 변신하지 않은 메타몽의 스피드파우더도 계산합니다. 변신 상태 자체는 지원하지 않습니다.
5. 속보는 주요 상태이상일 때 1.5배이고 마비 스피드 감소를 받지 않습니다. 그 외 **4세대 마비는 1/4배**입니다.
6. 슬로스타트 활성 여부, 곡예 발동 여부, 순풍 2배를 계산합니다. 계산기에서는 이 활성 상태를 입력으로 받습니다.

예를 들어 스피드 100 + 쓱쓱 + 비 + 스카프 + 마비는 `100×2×1.5÷4 = 75`입니다. 날씨부정이 있으면 `floor(150/4)=37`입니다.

행동 순서는 기술 우선도를 먼저 비교하고 그 안에서 스피드를 비교합니다. 트릭룸은 같은 우선도에서 느린 쪽을 앞세웁니다. 동속은 시드를 가진 난수로 선택합니다. 느림보꼬리·만복향로 및 시간끌기(Stall)의 후순위 처리를 포함했습니다. 선제공격손톱·애슈열매 같은 조건부 순서 변경은 미지원입니다.

## 4. 대미지는 계산 순서가 중요하다

근거 함수는 `CalcMoveDamage`, `DamageCalcDefault`, `ApplyDamageRange`, 타입 보정 함수입니다. 원본 `battle_util.c`, `battle_command.c`를 `reference/`에서 볼 수 있습니다.

일반적인 공격 기술의 흐름은 다음과 같습니다.

1. 물리면 공격/방어, 특수면 특공/특방을 선택합니다.
2. 특성·도구에 따라 위력이나 실제 공격/방어 수치를 수정합니다.
3. 능력치 랭크를 적용합니다. 급소는 공격자의 불리한 랭크와 방어자의 유리한 랭크를 무시합니다.
4. `floor(floor((floor(2×레벨/5)+2)×위력×공격/방어)/50)`을 계산합니다.
5. 화상, 리플렉터·빛의장막, 날씨 등을 순서대로 적용합니다.
6. **이 단계가 끝난 뒤 +2**를 더합니다.
7. 급소와 생명의구슬을 적용합니다.
8. 85~100 중 하나의 난수를 적용합니다.
9. 자속(STAB), 각 방어 타입의 상성, 필터·하드록/달인의띠/색안경 등을 적용합니다.

레벨 50, 위력 100, 공격 100, 방어 100, 자속·상성 등 보정이 없으면 난수 적용 전 46입니다. 화상이면 `44÷2 +2 =24`이며 `46÷2=23`으로 계산하지 않습니다. 이 차이를 테스트로 고정했습니다.

- 일반 급소는 2배, 스나이퍼 급소는 3배입니다.
- 기본 급소 확률은 1/16이며 원본 표는 1/16, 1/8, 1/4, 1/3, 1/2입니다.
- 스나이퍼/대운/급소 보정 도구와 배틀아머·조가비갑옷을 계산합니다. 기충전·종별 전용 급소 도구·주술은 미지원입니다.
- 자속은 1.5배, 적응력이면 2배입니다.
- 타입 표는 원본에서 추출했습니다. **강철이 고스트·악을 반감하는 4세대 상성**입니다. 페어리 타입은 없습니다.
- 부유·틀깨기, 불가사의부적, 건조피부의 물 흡수 면역, 검은철구와 비행/부유 관계를 포함합니다.
- 지구던지기·나이트헤드·소닉붐·용의분노는 고정 피해로 처리합니다. 자속·급소·난수와 무관하며 타입 면역은 확인합니다.
- 대미지 범위는 16개 난수를 전부 계산합니다. `ko_probability_on_hit`는 **명중했고 비급소/지정된 급소 조건이라는 전제**의 KO 비율이며, 전체 턴 승률이 아닙니다.

계산기의 `critical=True`는 급소를 강제로 가정하는 분석 옵션입니다. 실제 배틀에서는 특성까지 고려한 급소 확률을 별도로 추첨합니다.

## 5. 원본 배틀 AI 구조

`TrainerAI_Init`는 기술별 100점을 준비하고 사용 불가능한 기술의 점수를 0으로 만듭니다. 트레이너의 AI 플래그에 해당하는 스크립트를 선택하며, `TrainerAI_EvaluateMoves`가 명령 테이블을 통해 이를 실행합니다. 마지막에는 최고 점수 기술을 선택하고 동점은 무작위로 결정합니다.

`TrainerAI_SelectCommand`는 교체 가능성, 도구 사용 여부, 기술 사용을 확인합니다. 교체 후보 선택과 기절 후 투입 선택은 `battle_controller_opponent.c`에도 분산되어 있습니다. 원작 코드에는 싱글·더블 분기, 상대의 이전 행동 기록, 정보의 알려짐 여부, 대미지 예측과 특성·도구 판정이 있습니다. 따라서 `trainer_ai.c` 하나만 옮기면 원작 AI가 독립 실행된다는 설명은 정확하지 않습니다.

추출물:

- `ai_wordcode.json`: 10,607개의 32비트 워드와 32개 엔트리 오프셋. 오프셋은 바이트가 아닌 워드 인덱스입니다.
- `ai_commands.json`: 109개 opcode의 이름, C 소스 위치, 본문에서의 정적 `AIScript_Read(ctx)` 호출 개수.
- `reference/`: AI 및 전투 계산의 원본 소스.

정적 read 횟수는 자동 분석 참고값입니다. 조건 분기나 보조 함수가 추가로 읽을 수 있어서 이를 모든 명령의 완전한 인자 스키마로 간주하면 안 됩니다. 워드코드 안에는 명령뿐 아니라 참조 테이블도 있으므로 전부를 선형 명령으로 디코드해서도 안 됩니다.

`python -m battlelab original-ai --opcode 4`를 실행하면 실제 원본의 점수 가감 명령을 확인합니다. 원본은 점수를 더한 뒤 음수일 경우 0으로 제한합니다.

## 6. Python 실험 AI

`ai.py`의 점수 규칙은 원작 정확 이식이 아닌 새 정책입니다.

- 초기 100점, PP/구애 고정/지원 범위에 따른 합법 기술 필터링.
- 예상 대미지와 명중률에 따라 최대 약 +40점.
- 면역 -100점, 명중 시 비급소 확정 KO +20점, 해당 선공기 KO +10점.
- 회복·강화·상태이상 기술은 현재 HP와 효과 유효성을 기준으로 평가.
- 동점 기술은 시드 난수로 선택.
- 유효한 선택이 없거나 전부 0점이면 후보 포켓몬을 평가해 교체.
- HP 1/4 이하이며 회복 도구가 있으면 200 HP 회복 도구 사용.

AI는 시나리오의 상대 상태를 직접 읽는 **완전 정보 실험 정책**입니다. 원작의 상대 정보 제한/기억 모델은 이식하지 않았습니다. 난수 시드는 같은 실험의 재현을 위한 Python 난수이며 NDS의 난수열과 같지 않습니다. 원작 난수 순서까지 같은 결정을 보장하지 않습니다.

## 7. 실행 가능한 배틀의 범위와 한계

싱글 1~6마리 팀, 사용자 대 AI 또는 AI 대 AI를 지원합니다. 턴 시작 행동 선택, 우선도/스피드 순서, PP, 명중, 급소, 피해, 일부 부가효과, 화상·마비·독·맹독, 기절 및 자동 교체, 잔반, 생명의구슬, 구애 도구 고정을 포함합니다.

정확한 지원 목록은 `python -m battlelab supported`가 출력합니다. 데이터베이스에는 467개 기술과 NONE이 있지만 모든 기술이 시뮬레이터에서 실행되는 것은 아닙니다. 타입·위력·명중률 등 데이터 조회와 효과 실행은 구별됩니다.

- 냉동빔의 피해 계산은 가능하나 얼음 상태는 미지원이므로 배틀에서는 거부합니다. 물의파동도 혼란 미지원 때문에 배틀에서 거부합니다.
- 건조피부·선파워·슬로스타트는 조건을 지정한 계산기에서 가능하지만 배틀 중 자동 발동·경과 처리는 미지원이므로 배틀에서 거부합니다.
- 수면·혼란·빙결·대타출동·방어·도발·앙코르·설치기·날씨 기술의 지속 턴·특성 발동 이벤트·진화·경험치·통신·더블/트리플 배틀은 구현하지 않았습니다.
- 시나리오의 날씨/벽/트릭룸은 실험 동안 유지되는 외부 조건입니다. 순풍 등도 계산 입력 플래그이며 원작 지속 턴 시스템이 아닙니다.
- 턴 종료는 간소화한 날씨 → 잔반 → 주요 상태이상 처리이며, 기절 후보는 살아 있는 파티의 첫 번째로 자동 교체합니다. 원작의 모든 잔여 효과 우선순위/강제 교체 인터랙션은 재현하지 않습니다.
- 금지된 기능은 조용히 무시하지 않고 가능한 범위에서 입력 오류로 거부합니다. 지원된 기능의 조합도 ROM 대조가 없으므로 완전 재현을 주장하지 않습니다.

## 8. 파일을 읽는 추천 순서

1. `examples/johto.json`으로 실험 조건을 익힙니다.
2. `models.py`의 `make_pokemon`에서 실능력치를 확인합니다.
3. `mechanics.py`의 `effective_speed`, `first_actor`, `damage`를 읽습니다.
4. `ai.py`에서 점수와 선택 이유를 바꿔 봅니다.
5. `engine.py`에서 한 턴이 어떻게 진행되는지 확인합니다.
6. `reference/`의 원본 함수와 결과를 대조합니다.

이 프로젝트에 ROM, SDK, 게임 그래픽은 포함하지 않았습니다. 원본 연구 코드·파생 데이터의 출처는 `NOTICE.md`와 `data/provenance.json`에 기록했습니다.
